# Codebase map

Maintained by `gameplay-programmer` (and `ui-designer` for UI scenes). Agents read this instead of crawling the project, then pull only the files their ticket touches. Update it whenever a system is added or moved.

## Godot project (`game/`)

Godot 4.7 .NET, C# (`YokaiFighters.csproj`, net10.0). Boot: `scenes/main.tscn` (`scripts/Main.cs`) changes to `scenes/fight.tscn`. Its C# loader will adopt the schemas below (YOK-40).

### Simulation core (`game/scripts/Sim/`, namespace `YokaiFighters.Sim`, YOK-15)
Pure C#, **no Godot types**, integers only, so it runs headless for tests and the harness bot and replays exactly from per-tick inputs.

| File | Purpose |
|---|---|
| `SimConfig.cs` | Fight constants (record with defaults; a data loader fills it later). Positions in **centi-units** (`Scale` = 100 per gameplay unit). Stage half-width, view width, body (push-box) width, max separation (screen walls), walk speed (C2), max health (C1), KO slow-down (V4); YOK-16 fight-wide hit fallbacks: idle hurtbox, default hit/block pushback, knockdown frames (placeholder, C4), counterhit +20% / +6 (C7). YOK-18 movement: `DashFrames` 18 / `JumpFrames` 40 (C2) with **proposed** dash distances (300 fwd, 240 back), jump height 250 and drift 8 units/frame; `JumpY(n)` integer parabola, `DashStep(n, dist)` exact per-frame split. Idle hurtboxes per stance, **proposed** for the designer (E5's 90x180 covers half a 1.8 m body): standing `IdleHurtbox` 90x360, `CrouchHurtbox` 90x200, `AirHurtbox` 90x280. |
| `FighterInput.cs` | `InputBits` flags + `FighterInput(Bits, Move)`: one fighter's **raw** input for one tick — absolute Left/Right/Up/Down, six attack buttons (LP MP HP LK MK HK) and Kihon's `Special` (K1/K2) — plus `Move` (0 = none, n = move slot n-1, sent on the tick a move is requested; `FighterInput.Attack(slot)`; YOK-21: 201-204 = special slot A-D, 205-208 = EX, `FighterInput.Special(slot, ex)`, no precision bonus). Device mapping, the AI (P6) and replays produce the bits; the input layer below turns them into commands. `Debug*` bits are YOK-15 placeholders (cross-up, flat strike) kept for the loop tests. |
| `Fighter.cs` | `Fighter` state (X/Y on the 2D plane, Facing ±1, health, KO, previous input for edge detection, queued damage) and move state (YOK-16): `Moves` by slot, `FighterState` (Idle, Attack, Hitstun, Blockstun, Knockdown), `MoveSlot`/`MoveFrame` (1-based), `MoveConnected`, `StunLeft`, `Guarding`/`Crouching`, `Actionable`, `CurrentMove`; `Fnv` state hashing; `SimRng` seeded xorshift32 (the only RNG gameplay may use). YOK-18: `Input` (the fighter's `InputReader`), `AirFrame`/`JumpDir`/`Airborne`, `DashFrame`/`DashDir`; states `Dash` and `Jump` (airborne, no control; lands into Idle). YOK-19: state `Thrown` (grabbed; `StunLeft` = break-window frames left). YOK-20: state `Burst`. |
| `MoveData.cs` | `MoveData` (YOK-16): one move's Lv 1 frame data as loaded: startup/active/recovery, damage, hitstun/blockstun, optional pushback, knockdown, low, `Hitboxes`/`Hurtboxes` as `TimedBox(First, Last, Box)` in gameplay units (x toward the opponent). `IsActive(frame)`, `TotalFrames`, `AdvantageOnHit/OnBlock`. Throws `FormatException` on what the sim can't run (missing numbers, hitboxes without hitstun/blockstun, hitbox outside the active window). Strength and meter_gain (YOK-20); `properties.projectile`, `properties.invuln`, `cancel_windows` (YOK-21, `MoveData.Specials.cs`); rejects a damaging projectile without hitstun/blockstun or a spawn frame after the move. `LoadDirectory(dir, includeSpecials: false)` skips kind `special` (the fight loads those into slots via `SpecialLoader`; tests keep the default and run fixture specials as plain slot moves). `KindOf(path)`. |
| `MoveData.Specials.cs` | YOK-21 partial: `ProjectileData` (spawn frame, speed units/tick, hitbox relative to the spawn point, hits, lifetime 0 = until off-screen, passes/absorbs projectiles, `MaxActive` default 1 = one per owner), `InvulnWindow`/`InvulnAgainst` (`InvulnAt(frame, kind)`; air = strikes from an airborne attacker; throw is read but not applied, E12), `CancelWindow` (frames + on hit/block/whiff). |
| `SpecialData.cs` | YOK-21: `SpecialData` = one kind `special` file: `Slot` (from `input.kata.slot`), `ExCost` (`ex.meter_cost`), Lv 1 frame data, Lv 2 `tuning`, Lv 3 `evolution.changes`, `ex.changes`. `Build(level, ex)` applies the effects in order (Lv 2 if level >= 2, Lv 3 if 3, then EX) to the Lv 1 JSON and parses it with `MoveLoader` (`Ex` set for V3 shake). `SpecialLoader.Parse/LoadFile/LoadDirectory` (only kind `special`; builds every level plain + EX at load so bad data fails early). `Effects.Apply`: `add`/`mul_pct`/`set` on a dotted path; a first segment that isn't a frame_data field resolves under `properties` (`projectile.hits`); `set` creates missing objects; conditional `when` is rejected here (modifiers' job). |
| `Fighter.Specials.cs` | YOK-21 partial: `Specials[5]` indexed by `SpecialSlot` (A-D) of `EquippedSpecial(Data, Level, Move, ExMove)`; `Equip`, `Unequip`, `LevelUp` (A3, cap 3; rebuilds from data). Move-in-play state: `ActiveMove` (what `CurrentMove` returns in `Attack`, normals included), `ActiveSpecial`, `ActiveEx`, `ActivePrecision`, `SpecialButtons`, `MoveBlocked`; `CancelUsed` (X3 bits, cleared on Idle). `CancelRule` record + `CancelFrom`/`CancelInto`. |
| `Match.Specials.cs` | YOK-21 partial of `Match`. `TryStartSpecial(i, slot, ex, precision, buttons)`: empty slot or projectile limit = false; EX spends `ex.meter_cost` via `TrySpendMeter`, without it the plain version comes out; precision = damage x (100 + `PrecisionBonusPct`)/100. `TryExUpgrade`: second punch/kick within `ExPressWindow` frames upgrades in place. `ExPair` = two punches or two kicks (**designer proposal**). `TryCancel`: the X1-X4 hook (held rule + data cancel window + outcome; into dash or a pending special; X3 once per combo). `Projectiles` (`Projectile`: owner, serial, firing `MoveData`, X/Y/Dir, Age, HitsLeft, AbsorbsLeft, `WorldBox()`); `StepProjectiles` (travel, lifetime/off-screen = box fully outside the camera view, then spawn on the move's spawn frame at the owner's feet, facing); `ResolveProjectiles` (clash: passes = ignore, absorb eats the other, else each loses a hit; then vs the defender's hurtboxes through `ApplyHit(..., projectile)`: push follows the projectile, no corner hand-off, owner's move not marked connected). | `CancelRuleLoader.cs`, `SimConfig.Specials.cs` | YOK-21: kind `cancel_rule` → `CancelRule`; `PrecisionBonusPct` 10 (K1), `ExPressWindow` 3 (**proposed**). |
| `Match.cs` | One round (`partial`; throws in `MatchThrows.cs`). `Step(in1, in2)` = exactly one 1/60 s tick. Phases `Fighting → KoSlowMo → Over`. `Step` runs `HitstopStep` (YOK-20) before `WorldStep`. World step order: `AdvanceThrows` (YOK-19) → per fighter `AdvanceState` (jump arc + landing, move/dash frame +1, stun countdown; stun ending mid-air falls as `Jump`) then input: `Fighter.Input.Update(raw, facing)`, `TryBurst` (YOK-20), then if `Actionable`: explicit `input.Move` slot (tests/AI) > `FighterInput.Special` request (YOK-21) > `FindThrow` (YOK-19, raw buffer; also from a throw-button normal still in startup) > parsed command (Special → `TryStartSpecial` on its slot, else / empty slot → `FindNormal`: button + direction; a listed direction beats any-direction); while in `Attack`: `TryExUpgrade` else `TryCancel` (YOK-21) > jump (up held; drift from 7/9) > dash (66/44) > crouch/walk; guard = hold back, standing or crouching, grounded only (C3, E6) → `ResolveThrowBreaks` (YOK-19) → `ResolvePositions` (screen walls, push boxes and corner fix only when both grounded so jumps cross over, stage corners) → `UpdateFacing` (only `Idle` fighters turn; facing is held during moves, stun and knockdown) → `StepProjectiles` (YOK-21) → `ResolveThrows` (YOK-19, before strikes) → `ResolveHits` (both sides' active hitboxes vs the other's hurtboxes, mirrored by facing, applied together so trades work; one connect per move; body hurtbox by stance (`BodyHurtbox`); blocked unless a low meets a standing guard; an air hit stops drift and the arc continues; counterhit if the defender was in a move; hitstun/blockstun/knockdown, damage, pushback with corner hand-off; `Hit` event with `HitEvent`, then `OnConnect` for meter/hitstop; `properties.invuln` against strike/air skips the hit) → `ResolveProjectiles` (YOK-21) → `ApplyDamage` (simultaneous; double KO = draw). Timing: a move started on tick t plays frame n on tick t+n-1 and acts again on t+Total; N stun frames set on tick h hold h+1..h+N; so advantage = stun − (Total − hit frame). `QueueDamage()` stays as an external hook. KO: inputs ignored, world advances every 2nd tick for 30 world frames (V4), then `Over` until `Reset()`. `StateHash()` for determinism checks. Events `KnockOut`, `RoundOver`. |
| `MatchThrows.cs` | YOK-19 generic throws (C4), `partial Match`. A throw is a kind `throw` move the thrower plays like any Attack (its grab clip); the defender only gets `Thrown` then the standard `Knockdown` (E4), no paired clip. `FindThrow`/`ThrowPressed` (E12): all throw buttons pressed within `SimConfig.ThrowPressWindow` (3) ticks, the last this tick, read from the raw `InputBuffer` so Kata and Kihon share it (K3); `InThrowCancelableStartup`: a normal started by a throw button and still in startup is cancelled into the throw, otherwise the input is ignored. `Throwable(d)`: grounded, not `Invulnerable` (burst), and Idle, Dash or Attack (not airborne, hitstun, blockstun, knockdown, thrown, burst, KO). `ResolveThrows`: active throwboxes vs the defender's stance body box (`BodyHurtbox`), both sides together: both = `Clash` (auto-break), one = `Grab` (defender `Thrown` for `BreakWindow` ticks, block ignored). `ResolveThrowBreaks`: a Thrown defender who presses the thrower's buttons (same `ThrowPressed` leniency) breaks; a Thrown fighter can't burst (TryBurst needs Hitstun) (both Idle, slid apart by `on_break`, command consumed). `AdvanceThrows`: window closed → `Land`: damage, `Knockdown` for exactly `KnockdownFrames` ticks incl. the landing tick, slide by `on_hit`, raises `Hit` too, then `OnConnect` (C5: +6 thrower, +3 thrown; hitstop 12 and shake: throws default to `HitStrength.Heavy`, E12). Timing with the press on tick 1: grab tick 6, break ticks 7–13, lands tick 14 (then 12 hitstop ticks), defender acts 40 world frames later. Event `Throw` (`ThrowEvent`: Grab/Land/Break/Clash). Same-frame grab vs strike: grab wins (E12). |
| `Match.Meter.cs` | YOK-20 partial of `Match`: meter (C5), burst (C6), hitstop (V2). Hooks in `Match.cs`: `Step` runs `HitstopStep` before `WorldStep` (while `HitstopLeft` > 0 the world doesn't advance: `Tick` counts, `WorldFrame` holds, inputs still feed the readers, a burst can fire and ends the freeze); `TryBurst(i)` right after each fighter's `Input.Update`; `ApplyHit` calls `OnConnect` (attacker +6 hit / +3 blocked, or the move's `meter_gain`; defender +3 hit taken; cap 300; `HitstopLeft` = max of the connects, `Impact` event `ImpactEvent(Attacker, MoveId, Strength, Hitstop, Blocked, Counter, Shake)`); `Connects` skips `Invulnerable` defenders; `Reset` → `ResetMeterState`; `StateHash` adds meter/burst/hitstop. A connect on tick h freezes h+1..h+N for both fighters, so advantage = stun − remaining frames still holds. Burst: from `Hitstun` only, once per fight, LP+MP+HP all pressed within `BurstPressWindow` (3, **proposed**) ticks and held → `FighterState.Burst` for 20 invulnerable ticks (incl. the burst tick), meter → 0, opponent thrown back `BurstPushback` (200 units, **proposed**), `BurstFired` event. EX hook for YOK-21: `TrySpendMeter(i, cost)` / `TrySpendEx(i)` (1 bar). |
| `Fighter.Meter.cs`, `SimConfig.Meter.cs`, `MoveData.Impact.cs` | YOK-20 partials: `Fighter.Meter`/`BurstUsed`/`Invulnerable`/`TrySpendMeter`; config (bars, gains, `BurstFrames`, hitstop 6/9/12 +4, `HitstopEnabled`, `ShakeFrames`); `HitStrength` enum + `MoveData.Strength`/`Ex`/`MeterOnHit`/`MeterOnBlock`, read by `MoveData.ReadImpact` from `frame_data.strength` (else normals by button: L light, M medium, H heavy; other moves medium) and `frame_data.meter_gain`. |
| `FixedStepClock.cs` | Integer-microsecond fixed-step clock: `Advance(nowUsec)` returns the ticks due so exactly 60 ticks run per second at any render rate; caps catch-up at 8 and drops the rest on a hitch. |
| `FightCamera.cs` | Camera centre X = fighters' midpoint clamped to the stage; `BothInView()` for tests. |

### Input layer (`game/scripts/Sim/Input/`, namespace `YokaiFighters.Sim`, YOK-17)
Pure C#, deterministic, shared by Kata and Kihon (K3): only the `ICommandParser` differs. Per fighter: `InputReader.Update(raw, facing)` once per tick, then the move system calls `TryConsume(out InputCommand)`.

| File | Purpose |
|---|---|
| `InputConfig.cs` | Timing in ticks (E7): `MotionWindow` 16 (first direction → press), `CommandBuffer` 5 (command waits to be consumed), `ChargeTicks` 40, `ChargeGrace` 8, `DashWindow` 12 (**proposed**, YOK-18: first tap → second tap), `HistoryTicks` 128; `MotionPriority` tie-break (623 > 236 > 214 > 22); `ButtonPriority` (heavy > medium > light, punch > kick). |
| `Numpad.cs` | Absolute bits ↔ numpad direction relative to facing (6 = toward opponent). SOCD: left+right and up+down cancel. |
| `InputBuffer.cs` | Ring buffer of raw `InputBits` (age 0 = now): `Dir(age, facing)`, `PressedAt(age)` (button edges), `HeldTicks(bits)` (hold-to-charge buttons). |
| `MotionParser.cs` | `Motion` enum (236, 623, 214, 22 for K1 slots A–D, plus `[4]6` / `[2]8` charge motions not in any slot) and `Matches` / `FinalStepAge`: backwards greedy subsequence match inside the window, directions read with the facing at the press (motions flip when sides switch). Lenience: 623 accepts 1 for its down, 22 any down/non-down. |
| `InputCommand.cs` | `InputCommand` (Kind None/Normal/Special, `SpecialSlot` A–D, Motion, chosen Button, full Pressed mask for two-button throws, Direction, `Precision` = Kata motion +10%, K1) and `ICommandParser`. |
| `KataParser.cs` | Kata (K1): on an attack-button press, the most recently completed K1 motion in the window → Special in its slot (ties by `MotionPriority`), else a Normal with its direction. Ignores `Special`. Kihon (YOK-23) adds a sibling parser: `Special` + direction → slot. |
| `InputReader.cs` | Per-fighter owner of buffer + parser + command buffer. A normal never replaces a waiting special; a newer special does. `Dash` (+1 = 66, -1 = 44, exact 6/4 after a different direction). Owned by `Fighter.Input` and driven inside `Match` (YOK-18); special commands map to slots in `Match.Specials.cs` (YOK-21), not in the parser. |

## Content data (`data/`) and schemas (`data/schema/`, YOK-12)

JSON Schema draft 2020-12. Every content file is one JSON object with a top-level `kind` that picks its schema.

| `kind` | Schema | Folder | Covers |
|---|---|---|---|

### Conventions
- **ids** are lowercase kebab-case and equal the file name: `data/moves/spirit-wave.json` has `"id": "spirit-wave"`. References (`clip`, `preset`) are ids, resolved as `data/clips/<id>.json` and `data/presets/<id>.json`.
- **Integers only** for gameplay numbers (determinism, F3): frames, units, percent. `mul_pct: 130` means ×1.3.
- **Frames** are 1-based from the move's first frame. Active frames are `startup+1 .. startup+active`. `"active": null` is the rules.md "—" (projectile carries the hit; needs `properties.projectile`, no body hitboxes).
- **Rects** are in gameplay units (1 unit = 1 px at 1920×1080) relative to the character's feet, x toward the opponent, y up.
- **Effects** (`{target, op, value, when?}`) are the single data-only change vocabulary for Lv 2 tuning, Lv 3 evolutions, EX versions and modifiers. `target` is a dotted path into frame data (`recovery`, `projectile.speed`, `properties.armour`); `op` is `add | mul_pct | set`; `when` is an on-screen/game-state condition, never a button.
- **Inputs**: each special stores `input.kata` (`{slot, motion}`) and `input.kihon` (`{slot, direction}`); allowed pairs are fixed by K1/K2 and both slots must match.
- **Levels**: `levels.1.frame_data` is the full Lv 1 data; `levels.2` is exactly one `tuning` effect plus a required `status`; `levels.3.evolution` needs a `preset`.
- **`status: "proposed"`** marks values awaiting the designer (e.g. every Lv 2 step, an open question). Allowed on any file and on Lv 2 / evolutions; the validator counts them.
- **`rules`** lists rules.md IDs; the validator rejects IDs that don't exist.
- Profiles' `when` values come from a fixed list of on-screen observations (P6); a button-press condition fails the schema.

### Validator (`tools/validate_data.py`)
```
pip install -r tools/requirements.txt        # jsonschema==4.26.0 (already in the dev container)
python3 tools/validate_data.py               # all of data/, skipping data/schema/ and any invalid/ folder
python3 tools/validate_data.py data/moves data/clips/foo.json
python3 -m unittest discover -s tools -p 'test_*.py'
```
Exit 0 = valid, 1 = errors, 2 = missing dependency. Errors print as `<file>: <field.path>: <message>`.
Beyond the schema it checks: id = file name; files in `data/<folder>/` have that folder's kind (`data/moves/` takes `special`, `normal` or `throw`); a normal's clip exists and matches its `frame_data` (F2); rule IDs exist; a special's clip exists and matches its frame data (total = frames_total, hit_start = startup+1, hit_end = last active frame; F2); hitboxes inside the active window; hurtbox/cancel ranges inside the move; Kata/Kihon slots match; starters are Ryo + common; cancel `offered_by` elder matches `source`; `boss` temperament and `tanuki` tier only for the Tanuki; clip hit_start ≤ hit_end ≤ frames_total.

### Samples
`data/samples/` holds one valid file per kind (Spirit Wave + its clip, a sample light punch normal + its clip, Will-o'-wisp, Fox Step, Kitsune patient). Paths print with `/` on every OS. `data/samples/invalid/` holds deliberately malformed files; the default run skips them and `tools/test_validate_data.py` asserts they fail with the expected messages.
